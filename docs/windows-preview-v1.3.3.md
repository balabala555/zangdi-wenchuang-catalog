# V1.3.3：ZIP解压版一次性迁移

旧03报错的原因是原文件夹没有`.git`。重启电脑或关闭服务器不能补出Git仓库，不需要再反复检查任务管理器。旧脚本自身无法从ZIP获取新代码，必须有一次新的迁移入口；本次提供约9KB的小工具包，不是完整网站ZIP。

## 只做一次

每完成一步再继续：

1. 下载[一次性迁移包](https://github.com/balabala555/zangdi-wenchuang-catalog/raw/refs/heads/test/vi-v1.3.0/tools/windows-migration-v1.3.3.zip)，解压。
2. 双击里面的“一键迁移.cmd”。Node.js已经安装，无需重装。若提示缺少Git，先从 https://git-scm.com/downloads/win 安装免费Git for Windows，再重新双击迁移入口。无需GitHub登录或管理员运行网站。
3. 在自动弹出的文件夹选择窗口中，选择**原网站项目文件夹**：进入后能看到`02-start.cmd`及`package.json`的那个文件夹，不能选外层Downloads目录。
4. 等待“迁移/配置成功”。工具会备份原项目、下载并校验测试分支，在独立固定目录创建标准Git仓库，自动打开新目录和测试网站。确认页脚v1.3.3。原文件夹和个人资料保留，不要删除。

通常新目录为`C:\Users\你的用户名\zangdi-preview`。如果它已被ZIP占用，会使用`zangdi-preview-git`；再冲突则使用带日期的独立目录，绝不覆盖。以成功窗口实际打印和自动打开的目录为准。以后只使用这个新目录，可把它固定到资源管理器“快速访问”。

原ZIP中的个人修改不会自动合并进新仓库，避免把原图、私人文件或未确认数据上传；这些文件在原目录及完整备份中原样保留，需要时再单独核对。本地浏览器清单仍按浏览器地址保存，不会因迁移自动删除。正常仍使用localhost:3000；若无关程序占用3000，自动改用空闲端口并提示，临时换端口看不到旧地址的清单不代表清单已被删除。

## 以后日常更新

**只双击新固定目录的`03-update.cmd`。**它识别并关闭本工具管理的当前目录预览，备份、校验、只快进更新，显示版本/提交/备份路径，自动重新启动网站。不必先找进程，不必再点02、不需反复下载ZIP。无更新时也明确显示“已经是最新版”并复用/启动预览。

只想打开已有版本时可双击02。普通第三方程序占用端口不会被关闭；本工具只用随机令牌认证自己的本地预览服务，不按进程名或旧PID批量杀进程。旧版手动启动且不受管理的服务器不会被强行结束，首次迁移前可以在旧黑色窗口按Ctrl+C；你已经重启过电脑则无需额外操作。

## 更新失败或需要恢复

- 有本地修改、错误仓库、分叉、候选校验失败时停止，不强制覆盖。保留窗口提示反馈即可，不要执行git init/reset或删除文件。
- 备份在原项目旁的`项目名-backups\日期-随机编号`，不放公开仓库。包含源文件、照片、忽略的私有资料；仅排除可重装的node_modules及.git内部文件，Git项目另用bundle保存完整历史。
- 双击04，会从备份生成**独立恢复目录**并打开、启动，当前项目和个人修改均保留；不会覆盖原目录。ZIP恢复副本可直接预览，原标准Git固定目录仍保留。Git恢复副本可用05返回测试分支，再用03更新。
- 迁移中断或网络失败时原ZIP目录保持不变；未通过校验的临时克隆会清理。成功备份不会自动删除，会累计占用本地磁盘，可在确认版本后自行私有归档；磁盘不足时停止，不删除原文件。首次迁移若在创建Git仓库之前失败，尚无新04入口，原ZIP仍可用原02预览，修复网络/Git后重新运行同一个迁移包即可。

迁移和更新不推送代码、不合并main、不发布网站，不引入收费服务。Windows文件夹选择和双击操作仍待真机验收；云端测试没有冒充真实Windows测试。
