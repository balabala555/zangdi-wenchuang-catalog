# V1.4.1：修复原3000顾客网页不读取后台商品

## 原因与修复

上次只让08端口3200读取本机商品库，而02 / localhost:3000仍启动原静态资料。不是你保存失败，也不需要重新录入商品。

现在已将**02、npm启动和直接启动server.js**在此后台测试项目中的启动路径接入同一只读适配器；原顾客页面、详情、购物清单和图片导出继续复用，不重做网站。3000直接读取07同一Windows账号下的现有商品目录，并展示在售、非演示、不在回收站的商品及在售款式。

另修复“版本号同为1.4.1就复用旧进程”的问题：现在还校验资料来源和代码修订号。当前目录管理的旧静态进程可以安全重启；其他目录占用3000时明确停止并提示，不悄悄换到3001让用户继续看旧网页，也不强杀其他程序。

3. 双击新目录的 **02-start.cmd**。本次不要求用08，不重新初始化、不迁移商品，也不需要手工改资料文件。
