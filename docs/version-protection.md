## 每次开发的检查

1. 从最新测试分支继续，不改用 main 或旧下载目录。
2. 修改前核对页脚版本、src/version.js 和 CHANGELOG.md，保留工作区备份。
3. `npm run check`：只读版本保护检查、全部自动测试、图片生成校验及构建。启动和构建也自动执行版本保护检查。
4. 需要时运行 README 中的浏览器回归脚本，覆盖搜索、分类、款式、滑动、数量、旧清单兼容、金额、文字复制、真实图片、二维码、PNG及分享/保存。
5. 在苹果/安卓/微信真机复测后再验收。没有授权不合并 main 或部署。

`config/accepted-baseline.json` 记录7张确认品牌/二维码文件摘要、既有商品/款式关系及图片处理版本。`verify:release` 检查版本一致、素材完整、全部被商品引用的图片尺寸及旧兼容路径摘要，并扫描 public 和 Git 待提交文件（含 HTML 内嵌图）防止已知原图或设计源文件暴露。发现旧品牌静态文字、旧处理配方、缺图或素材变化时停止。

新增商品是允许的；原有商品价格、款式关系或正式品牌素材需要更换时，必须有明确业务修改依据，同步审查基线与变更日志。不要为了通过检查直接删掉基线或关闭素材校验。检查无法防止人员刻意删除保护脚本或切换整个仓库到旧版本；它是开发与启动时的回归门槛，不是权限控制系统。

## 私有文件

无水印原图放 `.private-originals/`，源设计放 `.private-designs/`，都不提交。常见 PSD/AI/Sketch/FIG/XD 等设计源扩展已忽略，版本检查也拒绝它们出现在 public。新格式需审查后补充。任何已跟踪文件不受新增 gitignore 自动保护，提交前仍须检查暂存内容。未知或改过字节的原图无法仅靠已知 SHA 全面识别，上传流程仍必须坚持私有输入、公开派生图。
