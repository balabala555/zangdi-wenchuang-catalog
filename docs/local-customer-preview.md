# 原顾客端接入本机商品库：Windows选购联调

沿用V1.4.1当前`test/admin-v1.4.1-soft-watermark`测试分支；不新建网站、不发布、不写入商品库。

## 为什么之前看不到后台商品

原顾客网站从程序内的静态`src/data.js`读取9件示例/原实拍商品；07后台保存到仓库外`%LOCALAPPDATA%\ZangdiCatalog\merchant-data`。两者此前刻意分离，没有自动发布或同步。

本次复用原首页、分类、搜索、详情相册、清单、文字复制、PNG与分享代码，增加**08本机只读入口**。它从已有CURRENT和已校验快照读取商品，在内存中转换为原顾客端数据格式；不初始化数据、不迁移、不复制商品到公开目录、不上传服务器。图片请求只提供登记过的水印展示图，原图不经HTTP公开。

## Windows：只需启动08

1. 保留旧文件夹，下载[当前测试分支ZIP](https://github.com/balabala555/zangdi-wenchuang-catalog/archive/refs/heads/test/admin-v1.4.1-soft-watermark.zip)，全部解压到新文件夹。
2. 双击新目录 **08-customer-preview.cmd**，保留黑色窗口。已有Node.js即可；08无需重新安装数据库或初始化商品库，也不要求导出、重复录入、上传照片。
3. 浏览器会自动打开原顾客端。顶部应显示 **“本机真实商品测试预览”**。若未打开，将黑色窗口中的`http://127.0.0.1:3200/`复制到浏览器地址栏。只在运行08的同一台Windows电脑访问。
4. 搜索“金卡”和“转经筒”，逐件进入详情测试。不要使用旧02入口检查后台商品：02仍是原静态顾客版本；08才读取本机资料。

07后台可同时运行在3100端口，08用3200端口，两者不会互相覆盖。后台修改并保存后，直接刷新08顾客页面即可读取最新资料。关闭08：黑色窗口按Ctrl+C；只关闭网页不会停止服务。3200已占用时不强杀进程，先查看是否已有08窗口。

## 实际读取规则

- 展示本机库中**在售、非演示、不在回收站**的商品；保留其他已保存真实商品，不仅限本次3件，不按名称硬编码价格。
- 商品和款式名称、单位、分类、规格、介绍直接读取已保存值。只展示在售款式；款式未独立定价就沿用商品价，否则显示款式自己的价格。
- 原三件商品若保存为2元/张、5元/张、3元/个，会按这些实际保存值展示；程序没有伪造或覆盖这三件商品记录。
- 多款式必须使用明确关联的款式照片。缺图显示提示，不借用其他款式图片；若原来只上传到公共照片而没有关联，需在07中选择对应款式后保存，不必重新上传/录入。
- 单款商品仍可使用公共/封面图。已有水印保持原样，不生成新水印、不改原文件。
- 资料排序及置顶沿用后台，首页人气区域在本机模式使用当前商品，不再引用不存在的旧示例商品。
- 本机预览清单与原静态站清单使用不同浏览器存储键，不覆盖原清单。刷新会按当前可用商品/款式重新校验、以当前价格重新计算；它是选购意向，不是锁价订单。
- 不开放管理API，不能从顾客预览保存、删除或发布商品。原离线网站下载在08中关闭，避免错误下载静态演示商品；PNG清单、文字复制和分享仍可用。

## 建议对真实3件商品验收

1. 07中确认三件均在售、每件5个款式为在售，并已有对应配图。
2. 08依次搜索并打开三件商品。每款逐个点击，核对照片、名称和价格：未开光版2元/张、开光版5元/张、转经筒3元/个（或你实际设置的款式价）。
3. 每件选择一个具体款式，分别加入2、3、4件；统一单价分别为2、5、3时，参考合计应为 **31元**。如果设置了款式独立价格，则按该款式价计算。
4. 检查三行款式名称、单价、数量、缩略图和小计，再生成图片清单。核对照片与选择一致、合计正确、双客服二维码清晰。
5. 刷新页面检查清单保留。后台改一项测试资料并保存，刷新顾客页确认新值；实际商品不要为了测试随意改价。
