# 商品图片水印与原图保护

本功能只使用本地开源工具：sharp、官方 `@img/sharp-wasm32` 和固定中文文字 PNG 图层。无付费 API、收费插件或在线图片上传处理。字体图层来自 Noto Sans CJK SC；浏览器和 Windows 无需安装该字体。

## 当前规则

- 固定水印为“扎西德勒鸭”，半透明低饱和度，三处斜向分布于图片内部，避免只有角落水印。它不是防盗或不可裁剪的技术保证。
- thumb 240、card 640、detail 1600 最长边，不放大、不裁切、不调色、不美化。缩略图和列表图保留无损 WebP 编码；详情在带水印的无损 WebP 与 JPEG quality 94、4:4:4 中选择体积更小者，绝不退回无水印原图。JPEG 有编码误差，不声称水印以外每个像素均完全不变；私有原图保持原字节。
- 所有尺寸从私有原图独立生成，水印图层、位置、压缩参数和源图摘要写入处理签名。重复处理校验并复用结果，绝不把上次公开图再加一层水印。
- 商品数据中的原有公开 URL 现返回带水印的兼容 JPEG；旧的已跟踪派生文件也替换为带水印内容，没有删除文件或改写历史。只有当前内容摘要派生 URL 使用 immutable 缓存；旧 URL 要重新校验。客户端先前缓存的旧文件不能被网站强制收回。
- 列表、详情、各款式、清单和 PNG 都消费同一款式的带水印输出；不支持 WebP 的浏览器回退至同一照片的带水印 JPEG。单文件离线 HTML 只内嵌带水印详情图。

## 新增商品

1. 将原始照片放入 `.private-originals/商品目录/文件.jpg`。例如公开路径是 `public/images/felt-mushroom-bag/light-gray.jpg`，对应本地输入是 `.private-originals/felt-mushroom-bag/light-gray.jpg`。还可以用 `CATALOG_ORIGINALS_DIR` 指定仓库以外的原图根目录。
2. 按既有模板在商品数据中配置公开路径及款式映射，不把原图复制到 `public/`。
3. 运行 `npm run images`，或正常运行 `npm run dev` / `npm run build`。水印、压缩、分尺寸输出自动完成；它们读取同一私有源，无法读取私有源且没有校验通过的公开输出时明确报错，不会用公开图冒充原图再次处理。
4. `.private-originals/` 已被 `.gitignore` 排除，且内置服务器不提供该目录。必须在自己的电脑另外备份；GitHub ZIP 不包含无水印原图。不要强制添加忽略文件，也不要把附件 ZIP 或整台工作区备份上传到公开仓库。

## Windows sharp 加载修复

- `@img/sharp-wasm32` 与 sharp 固定为相同版本，作为显式构建依赖安装。sharp 原生 DLL/CPU/平台模块不可用时，官方加载器会尝试 WASM 版本。
- 在 Windows 使用支持的 Node.js（>=20.9，推荐 LTS），项目目录先运行 `npm ci --include=optional`。不要复制其他机器的 `node_modules`。
- 已下载的完整水印输出会先校验摘要，已有图片预览和重建不需要导入 sharp，也不需要下载私有原图。新增图片或更改处理规则时才加载图片引擎。
- 自动化已模拟原生模块不可用，验证 WASM 的中文 PNG 合成、ICC 和 WebP 编解码；没有宣称已在真实 Windows 机器上执行。`node scripts/check-sharp-fallback.cjs` 可重复此模拟测试。用户仍需 Windows 真机复测。

本轮在取得远程 refs 后检查本地可达 Git 对象及历史 `dist/index.html`，确认：

- `da8bcf9` 开始包含三张无水印商品 JPEG。
- `ccabac0` 和 `7a28974` 的离线 HTML 内嵌过无水印原图。
- `7a28974` 还保存过无水印 thumb/card/detail 派生文件；旧详情副本与原图字节相同。
- 本轮仅替换最新测试分支公开文件的内容，不删除文件、不重写历史；旧提交、已有下载和缓存中仍可能取得无水印照片。不能将最新树的水印处理描述为历史原图已清除。

建议：先在私有位置备份原图，再另行明确授权清理范围。若确定要清除历史，需要协调所有相关分支、标签、fork/克隆和潜在 PR 引用，使用专门的历史清理流程，并视需要联系 GitHub 处理缓存引用。此类操作会改变提交编号、可能需要强制推送，不属于本轮授权，也不能保证收回他人已经下载的副本。不要通过删除主分支或盲目重置仓库来处理。

`node scripts/audit-public-images.mjs` 只读报告当前已跟踪/待跟踪文件与已知原图字节的匹配、可达历史中的原图对象及内嵌原图的 HTML 提交，不删除或修改任何 Git 历史。它不能证明未获取的远程引用、GitHub 缓存或外部下载已清理。
