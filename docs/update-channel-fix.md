# 修复03更新通道：在C:\zangdi-catalog直接更新并启动真实商品网页

软件仍V1.4.1，标记“03更新通道修复版”。本轮不新增启动脚本。

## 根因

电脑原03硬编码跟踪`test/vi-v1.3.0`，远程停在V1.3.3 / 6edf097。此前修复在`test/admin-v1.4.1-soft-watermark`，只推该分支不会改变原03的更新结果。因此它显示“已经是最新版”，却永远拿不到3000端口读取后台商品的代码。

本轮将原测试更新通道**安全快进**到修复版本（6edf097是修复分支祖先，无需强制覆盖或改写历史），同时更新当前开发测试分支。保留恢复标签`restore/vi-v1.3.3-6edf097`。main不变，不触发部署命令、不创建发布。

新版03按当前受支持的测试分支获取对应远程：

- 原固定目录：`test/vi-v1.3.0`。
- 新版后台测试目录：`test/admin-v1.4.1-soft-watermark`。

不会擅自切换分支、更新main、覆盖未提交修改或抹掉分叉。以后发布本轮测试修复时需同步维护这两个测试通道，避免再次出现只推开发分支却让旧03无更新。

## Windows最少操作

**直接双击原目录 `C:\zangdi-catalog\03-update.cmd`。** 不下载新ZIP、不新增入口、不重新录入、不移动商品库。

03会关闭属于当前目录的旧顾客服务、备份程序和Git恢复点、检查候选版本、只快进更新，然后自动启动顾客网页。新的更新器会在更新后启动新代码进程，避免继续用旧脚本内存逻辑。

核对结果：

- 版本应是 **V1.4.1**，不再停在V1.3.3 / 6edf097。
- 启动窗口出现“顾客网页读取本机商品库”。
- 浏览器打开 `http://localhost:3000/`，顶部显示“本机真实商品测试预览”。
- 搜索“金卡”“转经筒”，查看本机保存的三件商品和具体款式。

07后台可以保持运行；不用重新初始化。后台保存后，在顾客页刷新即可读取。

如提示3000仍由其他目录的旧窗口占用，只关闭那个旧**顾客网站**黑色窗口，然后双击当前目录02；不用关闭07或重启电脑，不会强杀其他程序。如提示本地有修改/分叉/校验失败，请保留提示并停止，不手工reset、不覆盖文件。

商品和款式仍须在售、不在回收站；不擅自改状态。原演示记录不混入本机真实商品清单，缺款式图片不会借用其他款式。

## 保留商品、照片和历史

- 后台资料及原图在 `%LOCALAPPDATA%\ZangdiCatalog\merchant-data`，位于Git项目之外，程序更新不迁移、覆盖、重建或删除该目录。
- 03的程序备份包含原项目及Git bundle；商品库的完整ZIP/历史恢复继续由07负责，不能把程序备份冒充包含外置商品库的完整备份。
- 顾客网页只读校验快照、照片登记及水印衍生图；不调用管理写入、不公开原图，不重新添加水印。
- 原名字、价格、单位、分类、介绍、款式及照片关联直接沿用保存值。款式价、数量、清单、PNG保留前轮实现。
- 旧程序备份可由04恢复到独立目录；已使用新版图片配方/字段的商品库回退需先用07保存完整ZIP，并由维护人员确认资料恢复，不混用不兼容旧后台。
