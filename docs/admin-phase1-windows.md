# V1.4.0 第一阶段：Windows 本地商品管理测试

本指南用于获得本轮独立测试版本后。当前稳定V1.3.3没有07入口；本轮尚未推送GitHub，不要在旧目录寻找，也不要用03自行切换分支。提供Windows下载渠道需要用户另行确认推送测试分支。

## 启动（拿到测试代码后逐步操作）

1. 进入包含`package.json`、`02-start.cmd`的本轮测试项目根目录。
2. 双击新增的`07-admin.cmd`，保留黑色窗口。只需原来已安装的Node.js；不用安装服务器、数据库、npm依赖或sharp。
3. 浏览器会自动打开本地授权入口；若未自动打开，点击黑色窗口显示的完整网址。它以`http://127.0.0.1:3100/`开头，包含本次启动的随机授权，不要转发。网页加载后会自动从地址栏清除授权片段。
4. 查看页面顶部“仅管理本机资料，保存不等于发布”，确认导入9条已有资料（3件真实商品、6条原有演示商品）。名称、价格、分类和照片沿用现有资料。

管理服务只监听127.0.0.1，不开放局域网或公网。手机不能用电脑IP打开这个后台；顾客网站仍使用原有02入口和3000端口。关闭后台服务：在07黑色窗口按Ctrl+C。网页只关闭不会停止服务，再次启动若提示3100已占用，请继续使用原管理窗口，不会自动结束其他程序。

## 点击测试

- **新增商品**：填写名称、七大分类、价格、单位、尺寸、材质、介绍、状态和颜色款式，点击“保存到本地”。新商品默认下架；保存只进入本机商品库。
- **编辑**：修改资料或切换在售／售罄／下架，保存后关闭并重新打开后台，确认资料仍在。旧分类原值保留；新商品不能误选旧演示分类。
- **搜索／状态筛选**：按名称、分类或款式检索；状态是本地记录，暂未同步顾客端。
- **预览**：查看已保存的单品资料与原有受保护照片。新增无照片商品会明确显示“尚未配置照片”。不是顾客网站整站发布预览。
- **备份与恢复**：可“立即备份”、下载资料备份，或选择历史快照/备份文件。恢复需先了解影响，再勾选确认；恢复整个商品库而非单件商品，当前和旧版本继续保留。

建议先新增一条明确命名为“本地测试草稿”的资料，练习编辑与恢复，不必改三件真实商品。没有商品永久删除功能；需要停用使用“下架”。照片上传、排序、删除及发布按钮本阶段不开放。

## 私有资料在哪里

默认：`%LOCALAPPDATA%\ZangdiCatalog\merchant-data`，通常位于`C:\Users\你的用户名\AppData\Local\ZangdiCatalog\merchant-data`。页面会显示实际完整路径；它不在Git项目内。

`CURRENT`指向当前完整快照，`snapshots`保存前后资料版本；不需要手工打开或修改这些文件。保存中断时不会先删除旧版本。当前指针损坏会明确停止读取，仍可用管理界面选择有效备份恢复，不会自动覆盖为初始商品。

资料备份文件只包含商品资料及既有照片引用，不包含照片文件或授权令牌。本阶段原照片只读，不搬移、不删除；沿用你已有的照片/原图备份。图片上传阶段将补齐私有原图统一管理和完整图片备份。

快照保留在同一磁盘可防误编辑，不能防整块磁盘损坏。请使用“下载资料备份”另存到移动硬盘等私有位置，不要放进公开仓库。快照不自动清理，会累计占用本地空间。

## 更新与恢复边界

- 管理台资料在仓库外，程序更新或程序备份恢复不会自动用旧资料覆盖它；已有商品库不会重复导入原始商品。
- 原03仍针对`test/vi-v1.3.0`稳定通道。本轮独立分支`test/admin-v1.4.0-phase1`尚未接入该通道，03会安全拒绝此分支，而非把后台覆盖回旧版。不要手工切换或强制更新；后续经确认再衔接更新通道。
- 原04属于程序恢复；商品资料请用管理台“备份与恢复”，二者分开。原03没有备份外置商品库，外置资料由管理台快照和导出独立保护。

## 阶段限制

只适合受信任的单机运营，未做多账号权限、多人协同或两店实时库存同步。启动随机授权及Cookie/CSRF/来源校验用于阻止无授权和跨站操作，不是企业权限系统。

私有目录使用本地文件系统（默认Windows个人目录通常为NTFS），不要直接放在共享网盘或网络磁盘；写入锁依赖硬链接支持。硬盘、权限异常会停止操作并保留已有版本，不强制覆盖。

当前基础版资料上限8MB；文件导入上限10MB，不把图片二进制塞进商品资料。真正的Windows双击、默认浏览器打开、文件系统权限与3100端口兼容仍需真机验收。此阶段没有公网发布能力，不合并main、不引入付费服务。
